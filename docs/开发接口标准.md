# 开发接口标准（API Standard）

> 项目：个人专属智能知识库（本地私有化，Windows 桌面应用）
> 版本：v0.1.0（契约基线）
> 状态：生效
> 维护：联调工作树（中间关联接口调节-rocket）
> 权威来源：后端 FastAPI + Pydantic 模型导出的 `backend/openapi.json`（OpenAPI 3.1）。本文档解释约定，机器可读契约以 OpenAPI 为准。

---

## 1. 适用范围

适用于 Electron 桌面端（前端）与本地 Python 后端之间的全部 HTTP / SSE 通信，以及后端内部对接口层、服务层、数据层的边界约定。

不在本规范内：AI 模型供应商的第三方 API（由后端适配层封装，前端不得直连）。

## 2. 基础约定

### 2.1 传输

| 项目 | 约定 |
| --- | --- |
| 协议 | HTTP/1.1，仅监听 `127.0.0.1`，禁止 `0.0.0.0` |
| Base URL | `http://127.0.0.1:{port}/api/v1` |
| 端口 | 由 Electron 主进程启动后端时动态分配，通过 IPC 传给渲染进程 |
| 编码 | UTF-8 |
| 请求体 | `application/json`；上传使用 `multipart/form-data` |
| 响应体 | `application/json`；下载为二进制流 |
| 流式 | `text/event-stream`（SSE） |

### 2.2 认证

- 所有接口（除 `/health`）必须携带 `Authorization: Bearer <local_token>`。
- `local_token` 由 Electron 主进程在首次启动时生成（32 字节随机数），保存在 Windows 凭据管理器；启动后端时通过环境变量注入，渲染进程通过 IPC 获取。
- 后端启动时同时下发 token 摘要校验，token 不落明文日志。
- 认证失败返回 HTTP 401 + `code=20001`；token 失效返回 `code=20002`。

### 2.3 公共请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 是 | `Bearer <token>` |
| `Content-Type` | 视情况 | JSON 请求必填 |
| `Accept` | 否 | 默认 `application/json` |
| `X-Request-Id` | 否 | 客户端生成的 UUID；服务端原样回显，未传则服务端生成 |
| `Idempotency-Key` | 创建类 POST 建议必填 | UUID；同 key 在 24h 内重复提交返回首次结果 |
| `If-Match` | 更新时可选 | 值为资源 `version`，用于乐观锁 |

### 2.4 标识、时间与命名

| 项目 | 约定 |
| --- | --- |
| 资源 ID | UUID v7 字符串（小写带连字符） |
| 时间 | ISO 8601 带时区，统一 UTC，如 `2026-11-24T03:00:00Z`；前端负责本地化展示 |
| 日期 | `YYYY-MM-DD`（仅用于计划、里程碑等日期语义字段） |
| 字段命名 | JSON 一律 `snake_case` |
| 枚举值 | 小写英文 `snake_case`，如 `in_progress`、`trashed` |
| 空值 | 无值用 `null`，可选字段也必须出现，不允许“字段缺失”与 `null` 混用 |
| 布尔 | `true` / `false`，禁止用 0/1 或字符串 |
| 数值 | 金额/分值保留精度；进度为 0–100 整数 |

> 前端不得在组件内随意改名。若需要 camelCase，只能在 `src/api/mappers/` 统一转换。

### 2.5 版本管理

- URL 主版本：`/api/v1`。
- 允许的变更：新增字段、新增可选参数、新增枚举值（前端必须容忍未知枚举）、新增接口。
- 破坏性变更：删除/重命名字段、改变类型、改变语义、必填化。必须升 `/api/v2` 并保留 v1 至少一个版本周期。
- 契约变更流程见第 10 节。

### 2.6 AI 模型接入约束（仅 DeepSeek）

| 项目 | 约定 |
| --- | --- |
| 供应商 | 对话/生成仅 `deepseek`；向量嵌入使用本地模型，不走外部 API |
| 接入协议 | OpenAI 兼容 HTTP API |
| Base URL | `https://api.deepseek.com`（固定，不作为用户可改项） |
| 模型白名单 | `deepseek-chat`（默认，Agent 对话与工具调用）、`deepseek-reasoner`（推理与总结） |
| 密钥 | 用户在设置页输入，仅存 Windows 凭据管理器；接口只返回 `model.has_key` |
| 启用条件 | `model.has_key = true` 且 `privacy.allow_external_calls = true`；否则 AI 接口返回 `50001` |
| 数据范围 | 只发送完成当前任务所需的条目片段与对话，不上传整个知识库 |
| 超时/重试 | 60s 超时；仅网络错误与 5xx 重试 2 次（指数退避） |
| 流式 | `/agent/chat` 使用 SSE |
| 工具调用 | 所选模型不支持工具调用时，Agent 降级为无工具对话，并在响应中标记 `tool_calling: false` |
| 供应商校验 | `PATCH /settings` 传入非 `deepseek` 的 provider 或非白名单模型，返回 `40002` |
| 嵌入模型 | 本地 `BAAI/bge-small-zh-v1.5`（ONNX，512 维），随安装包内置或经用户同意下载并校验 sha256 |
| 嵌入执行 | 仅在本机 CPU 推理，禁止调用外部嵌入 API；索引元数据记录模型名与版本 |
| 重建策略 | 嵌入模型或维度变更时必须全量重建索引，旧索引标记失效 |

> 对话/生成不实现多供应商抽象层：`ModelGateway` 只保留单一 DeepSeek 适配器；向量嵌入由本地 `EmbeddingService` 负责，不经过 `ModelGateway`。后续扩展需按 `behavior` / `breaking` 变更流程登记。

## 3. 统一响应与错误码

### 3.1 成功响应

所有业务接口返回统一信封（HTTP 2xx）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "0199a3f2-8b1c-7d2e-9f00-1a2b3c4d5e6f"
}
```

- `data` 可以是对象、数组或 `null`；分页对象见 3.4。
- 删除成功也返回 200 + `data: {"id": "..."}`，不使用 204，保证信封一致。

### 3.2 失败响应

```json
{
  "code": 40001,
  "message": "title 不能为空",
  "data": null,
  "request_id": "0199a3f2-8b1c-7d2e-9f00-1a2b3c4d5e6f",
  "details": {
    "field": "title",
    "reason": "required"
  }
}
```

- `message` 为可直接展示给用户的中文短句；技术细节放 `details`。
- HTTP 状态码与 `code` 同时表达语义，二者不得矛盾。

### 3.3 错误码段

| 区段 | 含义 | HTTP 映射 |
| --- | --- | --- |
| 0 | 成功 | 200/201/202 |
| 10001–19999 | 通用/限流/服务状态 | 400/429/503 |
| 20001–29999 | 认证与授权 | 401/403 |
| 30001–39999 | 资源与冲突 | 404/409/410 |
| 40001–49999 | 参数与校验 | 400/422 |
| 50001–59999 | AI / 模型 / 向量 | 409/422/429/502/504 |
| 60001–69999 | 存储与文件系统 | 400/409/413/500/507 |

### 3.4 分页

请求：

```
GET /items?page=1&page_size=20&sort=created_at&order=desc
```

| 参数 | 说明 |
| --- | --- |
| `page` | 1 起，默认 1 |
| `page_size` | 默认 20，最大 100 |
| `sort` | 允许字段由各接口声明，默认 `created_at` |
| `order` | `asc` / `desc`，默认 `desc` |

响应 `data`：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0,
  "has_more": false
}
```

### 3.5 过滤与搜索

- 多值参数用重复 key：`?type=note&type=tex`。
- 时间区间：`created_from` / `created_to`，ISO 8601。
- 文本搜索统一参数名 `q`。
- 未知参数一律忽略（向后兼容），但非法值返回 `40002`。

## 4. 并发控制与幂等

### 4.1 乐观锁

- `Item`、`LearningPlan` 等可编辑资源带 `version`（整数，从 1 开始）。
- 更新请求体必须带 `expected_version`；不匹配返回 HTTP 409 + `code=30003`，`data` 中返回服务端当前对象。
- 成功更新后 `version + 1`。

### 4.2 幂等

- 创建类接口（`POST /items`、`POST /files`、`POST /ai/tasks`、`POST /reminders`）支持 `Idempotency-Key`。
- 相同 key + 相同请求体：返回首次结果，HTTP 200，`data` 中 `idempotent_replay: true`。
- 相同 key + 不同请求体：返回 HTTP 409 + `code=30002`。

## 5. 长任务与实时事件

### 5.1 长任务

耗时操作（向量重建、批量 AI 整理、图谱重建）返回 HTTP 202：

```json
{
  "code": 0,
  "message": "accepted",
  "data": {
    "task_id": "0199...",
    "type": "reindex",
    "status": "queued",
    "progress": 0
  },
  "request_id": "..."
}
```

任务状态机：`queued → running → succeeded | failed | canceled`。

- 查询：`GET /ai/tasks/{task_id}`（通用任务接口，索引任务同样适用）。
- 取消：`POST /ai/tasks/{task_id}/cancel`，仅 `queued/running` 可取消。
- 前端不得用高频轮询；默认 3 秒一次，且页面不可见时暂停。

### 5.2 SSE 事件流

统一事件格式：

```
event: message.delta
data: {"conversation_id":"...","message_id":"...","delta":"..."}

event: message.completed
data: {"message_id":"...","finish_reason":"stop","usage":{"input_tokens":123,"output_tokens":45}}

event: task.progress
data: {"task_id":"...","progress":42,"stage":"embedding"}

event: error
data: {"code":50002,"message":"模型调用失败"}
```

约定：

- 每 15 秒发送注释行 `: ping` 作为心跳。
- 客户端断开后服务端必须终止模型调用（避免资源泄漏）。
- 事件 `data` 必须是单行 JSON。
- 目前使用 SSE；仅当确需双向通信时才引入 WebSocket，需在《开发过程.md》登记决策。

### 5.3 系统事件

`GET /events/stream` 推送：`reminder.due`、`ai.task.completed`、`index.updated`、`item.changed`。

## 6. 文件上传与下载

### 6.1 小文件（≤ 50 MB）

`POST /files`，`multipart/form-data`：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 文件本体 |
| `title` | 否 | 缺省用文件名 |
| `tags` | 否 | 逗号分隔的标签名 |

返回 `{item: ItemOut, file_asset: FileAsset}`（与 `complete` 同形状）。`item.type=file`、`item.file` 与 `file_asset` 一致，`item.created_at` 为条目创建时间。该接口不承诺幂等，前端不要自动重试上传，失败由用户触发重试。

- 扩展名不在白名单或声明 MIME 与实际类型明显不符 → `40003`（415）。
- 超过 50 MB → `40004`（413），前端应改走分片上传。
- 文件名清洗（去路径分隔符/控制字符）后为空 → `40002`（400）。
- 文件列表使用 `GET /items?type=file`：`ItemOut.file` 含 `id/original_name/mime_type/size_bytes/sha256/download_url`；不新增 `GET /files` 列表接口。

### 6.2 大文件（> 50 MB）

1. `POST /uploads` → `{upload_id, chunk_size, chunk_count}`
2. `PUT /uploads/{upload_id}/chunks/{index}`（`application/octet-stream`，index 从 0 开始）
3. `POST /uploads/{upload_id}/complete` → `{item, file_asset}`

规则：

- 分片 5–20 MB，默认 8 MB。
- `POST /uploads` 请求体：`{original_name, size_bytes, mime_type, sha256, title?, tags?}`；返回 `{upload_id, chunk_size, chunk_count}`。
- 分片 `PUT` 请求体为 `application/octet-stream`，返回 `{index, sha256}`；`complete` 请求体为空，返回 `{item, file_asset}`。
- 下载命中 `Range` 时返回 206 与 `Content-Range`；完整下载返回 200。
- 每片返回 `sha256`；complete 时校验整体 sha256。
- 上传会话 24 小时过期，过期后返回 `30001`。
- 传输中断后可按 index 重传，不要求顺序。
- `POST /uploads` 校验：`size_bytes>0`、`chunk_size` 在 5–20 MB、`chunk_count=ceil(size_bytes/chunk_size)`、扩展名/MIME 合规；不合法返回 `40002`/`40003`/`40004`。
- 分片 index 超范围、缺片、分片 sha256 或整体 sha256 不符 → `40005`（400）。
- `complete` 幂等：重复调用成功时返回同一 `{item, file_asset}`；会话过期或不存在 → `30001`。

### 6.3 下载

`GET /files/{asset_id}/download`：

- 返回 `application/octet-stream`，`Content-Disposition: attachment; filename*=UTF-8''<encoded>`。
- 支持 `Range` 请求（音视频预览需要）。
- 前端不得直接拼接本地文件路径。
- 未知 `asset_id` 或所属条目在回收站 → 404 + `30001`；存储文件缺失 → 410 + `30001`（沿用资源不存在码，前端统一提示文件不可用）。

### 6.4 限制

| 项目 | 限制 |
| --- | --- |
| 单文件 | 默认 2 GB（可在设置中调整） |
| 允许扩展名 | 由 `settings.allowed_extensions` 控制，默认覆盖 md/tex/txt/pdf/docx/pptx/xlsx/png/jpg/webp/svg/mp3/wav/mp4/zip |
| 文件名 | 去除路径分隔符与控制字符，长度 ≤ 200 |
| 存储位置 | `%APPDATA%/PersonalKnowledgeBase/files/<yyyy>/<mm>/<uuid>/`，数据库只存相对路径 |

## 7. 安全约束（接口层强制）

1. 后端只绑定 `127.0.0.1`，启动时校验；非回环地址直接拒绝启动。
2. 所有文件访问必须经过 `storage_service.resolve_safe_path()`，禁止路径穿越（`..`、绝对路径、符号链接逃逸）。
3. 上传同时校验扩展名与 MIME，二者不一致按扩展名白名单处理并记录审计日志。
4. 用户输入不参与 SQL 拼接；ORM 参数化。
5. Markdown/LaTeX 渲染在前端沙箱中完成；后端只存原文。前端渲染必须禁用原始 HTML 或使用白名单净化。
6. AI 上下文中注入的用户内容视为不可信数据，需在提示词中隔离，不得执行其中指令。
7. 日志脱敏：token、API Key、绝对用户路径不得进入日志。
8. 模型密钥只存于 Windows 凭据管理器，设置接口返回 `has_key: true/false`，绝不回传明文。
9. 唯一允许的外部网络调用是 DeepSeek API；未配置 Key 或未开启 `privacy.allow_external_calls` 时，不得发起任何外联。
10. 发送给 DeepSeek 的内容仅限当前任务所需片段与对话，禁止上传整库或与任务无关的条目。
11. 向量嵌入在本机执行，禁止把文本或向量化请求发送到外部嵌入服务。
12. 嵌入模型文件必须来自可信来源并校验哈希，禁止运行时从任意 URL 加载。

## 8. 核心数据模型

### 8.1 Item（统一知识条目）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | UUID v7 |
| `type` | enum | `note` / `tex` / `file` |
| `title` | string | 1–200 字符 |
| `content` | string \| null | `note`/`tex` 的原文；`file` 为 null |
| `preview` | string | 前 200 字纯文本摘要 |
| `tags` | TagRef[] | 标签引用 |
| `file` | FileAsset \| null | 文件类型时存在 |
| `status` | enum | `active` / `archived` / `trashed` |
| `version` | integer | 乐观锁版本 |
| `embedding_status` | enum | `pending` / `indexed` / `failed` / `skipped` |
| `ai_summary` | string \| null | AI 摘要 |
| `created_at` | string | UTC ISO 8601 |
| `updated_at` | string | UTC ISO 8601 |
| `deleted_at` | string \| null | 软删除时间 |

约束：`type=note|tex` 时 `content` 必填；`type=file` 时 `file` 必填。

### 8.2 TagRef

```json
{ "id": "0199...", "name": "机器学习" }
```

```json
  ],
  "edges": [
    { "source": "n1", "target": "n2", "relation": "related_to", "weight": 0.6 }
  ]
}
```

`type`：`item` / `tag` / `concept`。`relation`：`tagged_with` / `related_to` / `prerequisite_of` / `references`。

## 9. 接口清单

> 所有接口省略前缀 `/api/v1`。请求/响应除特别说明外均为统一信封。

### 9.1 系统

### 9.2 条目 / 笔记 / TeX

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/items` | 列表；过滤 `type`、`tag_id`、`status`、`q`、`created_from`、`created_to` |
| POST | `/items` | 创建条目（note/tex/file 统一入口） |
| GET | `/items/{item_id}` | 详情 |
| PATCH | `/items/{item_id}` | 更新标题/标签/状态；正文走 content 接口 |
| DELETE | `/items/{item_id}` | 软删除（进回收站） |
| POST | `/items/{item_id}/restore` | 从回收站恢复 |
| GET | `/items/{item_id}/content` | 读取原文（`text/plain`，供编辑器） |
| PUT | `/items/{item_id}/content` | 保存原文，带 `expected_version` |
| GET | `/timeline` | 时间轴分组；参数 `from`、`to`、`group_by=day/week/month` |

正文读写约定（F3 / B2 对齐）：

- `GET /items/{item_id}/content` 返回 `text/plain; charset=utf-8` 原文，不使用信封。
- `PUT /items/{item_id}/content?expected_version=<int>` 请求体为 `text/plain; charset=utf-8` 原文；成功返回 `ItemOut` 信封（`version` 已递增）。
- 版本不匹配返回 409 + `code=30003`，`data` 为服务端当前 `ItemOut`；前端据此提示「刷新 / 覆盖」。
- `type=file` 的条目调用 content 接口返回 `40001`。

条目生命周期约定（I1 对齐）：

- `GET /items/{item_id}` 对回收站条目仍返回 200（`status=trashed`、`deleted_at` 非空），供回收站页展示；仅 id 不存在时返回 404 + `30001`。
- 回收站条目：content 读写、`PATCH`、标签关联/解除均返回 404 + `30001`；`POST /restore` 恢复为 `active`。
- `DELETE /items/{item_id}` 返回信封 `{id}`；软删除与恢复都会使 `version` 递增。
- `GET /items` 与 `/timeline` 默认 `status=active`；需要回收站数据时显式传 `status=trashed`。

时间轴响应约定（B3 / F4 对齐）：

- 参数：`from`、`to`（ISO 8601，含边界）、`group_by=day/week/month`、`tz`（IANA 时区，默认 `UTC`）、`cursor`（不透明串）、`limit`（默认 50，最大 200）、`type`（可重复）、`status`（默认 `active`）、`tag_id`（可重复）、`q`。`type/status/tag_id/q` 语义与 `GET /items` 一致。
- 返回：`{groups: [{key, label, item_count, items: [ItemOut]}], next_cursor, has_more}`；按 `created_at DESC, id DESC` 排序。
- `key` 按 `tz` 的日/周/月边界切分；`item_count` 为**本页内**该分组的条目数，跨页合并时前端按 `key` 累加。
- 跨页时 `groups` 只含本页条目，前端按 `key` 合并。
- 非法 `tz` / `group_by` / 时间区间 / 过滤值返回 `40002`；空区间返回 `{groups: [], next_cursor: null, has_more: false}`。

创建请求示例：

```json
{
  "type": "note",
  "title": "向量检索笔记",
  "content": "# 标题\n...",
  "tags": ["机器学习", "检索"]
}
```

### 9.3 标签

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/tags` | 标签列表，含 `item_count` |
| POST | `/tags` | 创建标签 |
| PATCH | `/tags/{tag_id}` | 重命名 |
| DELETE | `/tags/{tag_id}` | 删除标签并解除关联 |
| POST | `/items/{item_id}/tags` | 批量关联 `{tag_ids: []}` |
| DELETE | `/items/{item_id}/tags/{tag_id}` | 解除关联 |

标签约定（B3 / F4 对齐）：

- `GET /tags` 返回 `[{id, name, item_count, created_at}]`，按 `name` 升序；`item_count` 只统计 `active` 条目。
- 名称 `trim` 后 1–50 字符；ASCII 不区分大小写判重，重复返回 409 + `30002`。
- 删除标签只解除关联，不删除条目；重复关联幂等，解除不存在的关联返回 404 + `30001`。
- `POST /items/{item_id}/tags` 与 `DELETE /items/{item_id}/tags/{tag_id}` 成功变更关联时返回更新后的 `ItemOut`，并使条目 `version` 递增；重复关联（幂等无变更）不递增。客户端应使用响应中的 `version` 覆写本地值，避免后续保存误判冲突。

## 10. 契约变更流程

1. 后端先在代码中修改 Pydantic 模型/路由，重新导出 `backend/openapi.json`。
2. 在《开发过程.md》的「接口变更记录」追加一行：日期、接口、变更类型、说明、后端负责人。
3. 前端运行 `npm run gen:api` 重新生成类型，确认编译通过后在「前端确认」列填写日期。
4. 联调工作树更新本文档的接口清单（若涉及约定变化）并评审。
5. 未确认的契约变更不得合并到 `main`。

变更类型：`additive`（新增）、`behavior`（语义变化）、`breaking`（破坏性）。

## 11. 前端类型生成

- 后端 CI 产出 `backend/openapi.json`。
- 前端脚本：`npm run gen:api` → `openapi-typescript ../backend/openapi.json -o src/api/generated.ts`。
- 生成文件禁止手改；提交时与 OpenAPI 同一次 PR。
- 所有请求/响应类型必须来自 `generated.ts`，禁止手写重复类型。
