# 前后端分工与协作边界

> 项目：个人专属智能知识库
> 版本：v0.1.0
> 维护：联调工作树
> 配套文档：《开发接口标准.md》《开发规范.md》《开发过程.md》

---

## 1. 组织方式：三工作树

| 工作树 | 分支 | 角色 | 主要产物 |
| --- | --- | --- | --- |
| `后端-test-tube-langchain` | `lwc/后端-test-tube-langchain` | 后端实现 | FastAPI 服务、LangChain Agent、数据库、向量库、调度器、OpenAPI |
| `桌面端页面-high-voltage` | `lwc/桌面端页面-high-voltage` | 前端实现 | Electron 应用、React 界面、API 客户端、打包安装包 |
| `中间关联接口调节-rocket` | `lwc/中间关联接口调节-rocket` | 联调/评审/文档 | 接口契约、联调测试、文档、代码评审、进度管理 |

三个工作树共享 `main` 上的《开发过程.md》；各自只修改自己负责的行。

---

## 2. 职责总则

### 2.1 后端（Backend）负责

- 实现并维护 `/api/v1` 全部接口，保证与 OpenAPI 一致。
- 维护数据模型、迁移、索引、软删除与并发控制。
- 实现 LangChain Agent：工具、提示词、记忆、流式输出、引用。
- 实现向量化、检索、图谱构建、提醒调度、画像刷新等后台能力。
- 保证安全约束：回环监听、token 校验、路径安全、密钥隔离。
- 产出 `backend/openapi.json` 与契约测试。
- 对接口错误码、超时、重试、限流负责。

### 2.2 前端（Frontend）负责

- 实现 Electron 主进程、preload 安全桥、渲染进程界面。
- 实现 API 客户端、类型生成、错误提示、SSE 重连与取消。
- 实现编辑器（Markdown / TeX）、时间轴、标签、文件管理、搜索、AI 对话、任务中心、提醒、学习计划、图谱、设置。
- 负责交互体验、可访问性、加载/空/错误态、虚拟滚动。
- 负责打包、安装包、桌面通知、自动更新（如启用）。
- 对用户可见的所有文案与时间本地化负责。

### 2.3 联调（Integration）负责

- 定义并维护接口契约与开发规范。
- 搭建 Mock 服务与契约测试，保证前后端可并行开发。
- 执行联调验收清单，定位跨端问题（字段、时序、错误、并发）。
- 评审后端接口层与前端 API 层代码。
- 维护《开发过程.md》，跟踪进度、阻塞、决策与契约变更。
- 负责最终端到端验收与发布检查。

## 4. 协作流程

### 4.1 契约先行

```
后端定义/修改 Pydantic 模型
  → 导出 openapi.json
  → 在《开发过程.md》登记接口变更
  → 联调评审
  → 前端生成类型并确认
  → 双方并行实现
```

- 契约未确认前，前端不得基于猜测实现。
- 紧急情况下可先用 Mock，但 Mock 必须由 OpenAPI 生成，禁止手造字段。

### 4.2 并行开发

- 前端在 `src/api/mocks/` 使用 MSW，按 OpenAPI 生成响应。
- 后端每个接口完成后，在过程文件中把对应任务标记 `DONE`，并附接口路径。
- 联调工作树维护一份「可联调接口清单」，接口一旦可用即通知前端切换。

### 4.3 联调与验收

- 每个里程碑结束执行《开发接口标准.md》第 13 节验收清单。
- 发现问题记录到《开发过程.md》的「阻塞与待决」表，标明责任方与期望时间。
- 联调通过后，双方在过程文件中确认该里程碑 `DONE`。

### 4.4 代码评审

| 变更类型 | 评审人 | 重点 |
| --- | --- | --- |
| 后端接口层/模型 | 联调 | 契约一致性、错误码、分页、并发、安全 |
| 后端 Agent/工具 | 后端自评 + 联调抽检 | 提示词隔离、引用、超时、日志脱敏 |
| 前端 API 客户端/类型 | 联调 | 信封处理、错误映射、SSE 重连、类型来源 |
| 前端 UI | 前端自评 | 可访问性、状态覆盖、性能 |
| 契约破坏性变更 | 全体 | 版本策略、迁移方案、回滚方案 |

## 6. 升级与决策机制

- **技术争议**：先在过程文件登记「待决」，列出选项与影响；由联调工作树组织决策，记录结论。
- **契约冲突**：以《开发接口标准.md》+ OpenAPI 为准；文档与实现不一致时，先修实现或先改文档，二者必须同一 PR 对齐。
- **进度阻塞**：阻塞超过 1 天必须在过程文件标记 `BLOCKED`，写明需要谁、需要什么。
- **范围变更**：新增功能先改过程文件的任务表与里程碑，再开工。

---

## 7. 沟通纪律

1. 所有跨工作树的信息只通过《开发过程.md》传递，避免口头约定丢失。
2. 每次开工前先同步 `main` 并读过程文件，确认任务状态不是 `DONE` 或 `DOING`（防止重复劳动）。
3. 状态变更当天更新，不积压。
4. 接口变更必须留下记录，前端确认后才算完成。
5. 过程文件只写状态与结论，长文放 `docs/` 并链接。
